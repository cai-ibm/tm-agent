# Wiki Schema (Hermes Agent)

Роман (пользователь) называет агента «Туркмен».

## Domain
IT-инфраструктура и бизнес-процессы предприятия: серверы, сеть, сервисы (n8n, Nextcloud, OnlyOffice, Exchange, 1С), ERP-системы, корпоративные данные, безопасность, документооборот.

## Как Hermes работает с wiki

**Инструменты Hermes, которые используются:**
- `session_search` — поиск по прошлым сессиям для извлечения накопленных знаний перед ingest
- `memory` — долговременная память агента (дублируется в `raw/memory/` для seeded wiki)
- `skill_view` / `skill_manage` — навыки как процедурные знания
- `terminal` — shell-операции (git, поиск, скрипты)

**Обязанности агента:**
- Агент пишет и поддерживает wiki. Пользователь курирует источники и направляет анализ.
- При каждом ingest: прочитать источник → обсудить ключевые выводы → обновить/создать страницы → обновить index.md → дописать log.md
- При query: прочитать index.md → найти релевантные страницы → синтезировать ответ с цитатами (`[[wikilinks]]`)
- При lint: проверить орфанов, битые ссылки, противоречия, устаревшие данные

## Conventions
- **Язык:** русский (все страницы, index, log). Имена файлов: lowercase, hyphens (на транслите или английском)
- **Имена файлов:** `mail-ca-ibm-org.md`, `smtp-relay-ca-ibm.md`, `server-94-130-51-161.md`
- Каждая wiki-страница начинается с YAML frontmatter (см. ниже)
- Использовать `[[wikilinks]]` для связей между страницами (минимум 2 исходящие ссылки на страницу)
- При обновлении страницы всегда обновлять `updated` в frontmatter
- Каждая новая страница должна быть добавлена в `index.md` в правильную секцию
- Каждое действие должно быть дописано в `log.md`
- **Provenance markers:** на страницах, синтезирующих 3+ источников, добавлять `^[raw/articles/source.md]` в конец параграфов

## Frontmatter
```yaml
---
title: Заголовок страницы
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: entity | concept | comparison | query
tags: [из таксономии ниже]
sources: [raw/articles/source-name.md]
confidence: high | medium | low
contested: true                          # если есть неразрешённые противоречия
contradictions: [other-page-slug]        # страницы, с которыми конфликт
---
```

### raw/ Frontmatter
```yaml
---
source_url: https://example.com/article
ingested: YYYY-MM-DD
sha256: <hex digest тела после frontmatter>
---
```

## Tag Taxonomy
- **Инфраструктура:** server, network, service, container, docker, database, storage, vm
- **Сервисы:** n8n, nextcloud, onlyoffice, exchange, nginx, smtp, 1c, erp, bookstack
- **Безопасность:** vulnerability, audit, access-control, encryption, firewall, winrm
- **Данные:** employee, business-data, report, pto, document
- **Разработка:** github, git, script, python, automation
- **Мета:** comparison, howto, troubleshooting, procedure, inventory

Правило: каждый тег на странице должен присутствовать в таксономии. Новые теги добавлять сюда ДО использования.

## Page Thresholds
- **Создавать страницу** когда сущность/концепт встречается в 2+ источниках ИЛИ центральна для одного источника
- **Дополнять существующую** когда источник упоминает что-то уже описанное
- **НЕ создавать страницу** для мимолётных упоминаний
- **Разделять страницу** при превышении ~200 строк — выносить подтемы с перекрёстными ссылками
- **Архивировать** при полном устаревании — в `_archive/`, удалить из index

## Entity Pages
Одна страница на сервер, сервис, систему. Включает:
- Обзор / что это
- Ключевые параметры (IP, хостнейм, ОС, характеристики) — НИКОГДА не хранить пароли
- Таблицы параметров
- Связи с другими сущностями (`[[wikilinks]]`)
- Ссылки на источники

## Concept Pages
Одна страница на концепт или тему. Включает:
- Определение / объяснение
- Текущее состояние знаний
- Открытые вопросы
- Связанные концепты (`[[wikilinks]]`)

## Comparison Pages
Сравнительный анализ. Включает:
- Что и зачем сравнивается
- Измерения сравнения (таблица)
- Вывод / синтез

## Update Policy
Когда новая информация конфликтует с существующей:
1. Сверить даты — новые источники обычно приоритетнее
2. Если реальное противоречие — зафиксировать обе позиции с датами и источниками
3. Пометить в frontmatter: `contested: true`, `contradictions: [page-name]`
4. Вынести на ревью пользователю в lint-отчёте

## Hermes-специфичные workflow

### Ingest из памяти агента
Периодически дампить `memory` в `raw/memory/agent-knowledge-YYYY-MM-DD.md` и обновлять wiki-страницы. Это seeded source — вики знает то же, что и агент.

### Ingest из сессий
Использовать `session_search` для поиска знаний по теме в прошлых сессиях перед созданием/обновлением страниц.

### Git
После каждого значимого изменения — коммит и пуш в `cai-ibm/tm-agent`. Использовать `terminal()` для git-операций единым вызовом.
