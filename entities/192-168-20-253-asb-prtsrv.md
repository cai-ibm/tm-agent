# ASB-PRTSRV — принт-сервер (192.168.20.253)

**FQDN:** asb-prtsrv.ca-ibm.org  ·  **IP:** 192.168.20.253/24 (шлюз 192.168.20.254)  ·  **DNS:** 192.168.30.9 (GC1)
**Роль:** Windows Print Server — 66 общих очередей печати для всех площадок (Б1, Б2, К16, участки)
**Доступ:** WinRM 5985 + SMB, доменная учётка `cai\hermes` (админ домена). RDP выключен.

Открытые порты: **445, 139, 135** (SMB/RPC), **5985** (WinRM), **3389** слушается,
но RDP запрещён (`fDenyTSConnections = 1`). 80/443/631/9100/515 на самом сервере закрыты —
он не печатает сам, только раздаёт очереди.

Гипервизор не подтверждён — по модели ВМ это VMware; вероятнее всего [[entities/server-asb-07d-esxi]].

Порты — стандартные TCP/IP: **58 × 9100 (RAW)**, **8 × 515 (LPR, все Konica)**.

**Соглашение об именах:** `<инвентарный_номер>-<модель>` (`00001-HP_227`, `00042-HP_479`,
`00177-Konica_C251i`). Имя порта = номеру в имени очереди. Описание очереди — путь до рабочего места:
`<корпус>.<модуль>.<отдел>.<сотрудник>`, например `Б2.Модуль4.Бухгалтерия.Остапенко О...` —
по нему ищется принтер конкретного человека.

### Найти принтер по фамилии
```powershell
Get-Printer | Where-Object { $_.Comment -match 'Остапенко' } |
  Select-Object Name,PortName,ShareName,PrinterStatus
```

## Типовые операции
```powershell
# все очереди / состояние
Get-Printer | ft Name,DriverName,PortName,Shared,PrinterStatus -AutoSize

# зависшие задания в очереди
Get-PrintJob -PrinterName '00042-HP_479' | Select DocumentName,JobStatus,SubmittedTime
Get-PrintJob -PrinterName '00042-HP_479' | Remove-PrintJob

# перезапуск диспетчера печати (сбрасывает застрявшие задания)
Restart-Service Spooler

# проверка связи с самим принтером (порт из очереди)
Get-PrinterPort -Name (Get-Printer '00042-HP_479').PortName | Select Name,PrinterHostAddress,PortNumber
Test-NetConnection 192.168.20.60 -Port 9100

# смена IP принтера — менять на порту, не на очереди
Set-PrinterPort -Name 00042 -PrinterHostAddress 192.168.20.60
```
SMB-обзор сервера: 66 печатных очередей + `C$`, `IPC$`, `print$` (драйверы; x64 + x86-совместимый).
Драйверы — HP PCL6/PCL-6 V4, Canon Generic Plus UFR II (+V273), KONICA MINOLTA Universal PCL.

## Замечания
- **Журнал печати выключен.** `Microsoft-Windows-PrintService/Operational`: `Enabled=False`, лимит 1 MB →
  истории заданий (кто, что, когда печатал) нет. Включать: `wevtutil sl Microsoft-Windows-PrintService/Operational /e:true`
  и поднять размер; выключать по умолчанию — политика Microsoft, но учёта печати без этого не будет.
- **Свободно 16 GB из 39,2 на C:** — спул делит диск с системой. Большие задания (сканы PDF на Konica 515/LPR)
  при нехватке места встанут колом и положат весь сервер печати; место держать под контролем.
- **12 очередей не отвечали (09.11.2026), все Canon:** 00078 (.2), 00079 (.3), 00050 (.9), 00126 (.14),
  00065 (.15), 00132 (.17), 00145 (.22), 00219 (.31), 00036 (.53), 00085 (.45), 00176 (.41), 00275 (.38).
  Ни ICMP, ни 80/515/9100 — выключены или оторваны от сети; остальные 54 отвечают. Системность (только Canon)
  стоит проверить: питание/свитч их сегмента.
- **PrintNightmare-хардненинг не включён:** `RpcAuthnLevelPrivacyEnabled` отсутствует (=0),
  `PointAndPrint\RestrictDriverInstallationToAdministrators` не задан. Рекомендуется выставить 1 —
  но только после проверки клиентов (старые ОС/драйверы V3 могут отвалиться).
- **Статусы:** `00042-HP_479` и `00018-Konica_C250i` — `TonerLow`.
- NETLOGON 5719 в System (14.10, 08.10, 09.09) — на старте не было DC; на печать не влияет.
- SMB-сессии: `CAI\prtg` со 192.168.40.29 (PRTG мониторит сервер) и `CAI\ar.annayev` со 192.168.30.35.
