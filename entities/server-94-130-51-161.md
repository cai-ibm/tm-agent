### ⚠️ Policy routing (асимметричная маршрутизация)
Пакеты с подсетей 192.168.30.0/24 и 192.168.31.0/24 приходят на ens37, но ответ может уйти через default gateway ens34. Решение — policy routing:

- Таблица `ens37_rt` (100): default + 192.168.0.0/16 + 10.10.0.0/16 через 192.168.2.1 dev ens37
- Правило: `from all iif ens37 lookup ens37_rt priority 100`
- Автозапуск: netplan + systemd `ens37-policy-routing.service`

## MCP (Model Context Protocol) — n8n MCP сервер

Через MCP агент управляет n8n: поиск, создание, выполнение workflow.

**URL:** `https://n8n.ca-ibm.org/mcp-server/http`
**JWT токен:** в конфиге `~/.hermes/config.yaml`
**Транспорт:** HTTP (StreamableHTTP)

### Конфигурация Hermes Agent

```yaml
mcp_servers:
  n8n:
    url: "https://n8n.ca-ibm.org/mcp-server/http"
    headers:
      Authorization: "Bearer <JWT_TOKEN>"
    timeout: 180
    connect_timeout: 30
```

### Инструменты (13 шт.)

| Инструмент | Назначение |
|---|---|
| `search_workflows` | Поиск workflow по имени/проекту |
| `get_workflow_details` | Детали workflow: ноды, триггеры |
| `execute_workflow` | Запуск (manual/production, chat/form/webhook) |
| `get_execution` | Результаты выполнения по ID |
| `search_nodes` | Поиск нод n8n по сервису |
| `get_node_types` | TypeScript-типы параметров нод |
| `get_suggested_nodes` | Рекомендации нод по категориям |
| `validate_workflow` | Валидация SDK-кода |
| `create_workflow_from_code` | Создание workflow из SDK |
| `update_workflow` | Обновление workflow |
| `publish_workflow` | Активация workflow |
| `unpublish_workflow` | Деактивация workflow |
| `archive_workflow` | Архивирование workflow |

### Важно
- Workflow видны через MCP только если включено `availableInMCP: true` в настройках
- Для destructive операций (archive, unpublish) требуется подтверждение
- Перед созданием workflow — `validate_workflow`
- Перед написанием кода нод — `get_node_types`
